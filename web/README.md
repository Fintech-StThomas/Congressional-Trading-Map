# Paper Trail (web)

The public site: a board that maps every member of Congress to the organisations and colleagues they are tied to by filed records, with the records one click away. Next.js 16 App Router, TypeScript strict, plain CSS, d3-geo and topojson-client (build time only). No database and no server secrets: every page is prerendered from the JSON in `public/data`.

Live: https://red-paper-trail.vercel.app/ · Data contract: [`../docs/data-dictionary.md`](../docs/data-dictionary.md) · Review notes: [`REVIEW.md`](REVIEW.md)

## Directory map

```
web/
├── next.config.ts        dataset choice (real or fixtures), data year, /o/<id> rewrite, cache headers
├── scripts/              resolve-data (pick dataset), make-fixtures, screenshots, visual-snapshots, bundle-sizes
├── tests/                *.test.mjs: unit tests (pure lib code, no server) and smoke.test.mjs (Playwright)
├── fixtures/data/        invented sample dataset (used when public/data is absent)
├── public/data/          generated by the pipeline: never edit
└── src/
    ├── app/              routes: one folder per URL (page.tsx), plus build-time JSON routes
    ├── components/
    │   ├── board/        the home board: BoardApp (state), BoardCanvas (yarn), Toolbar, Slip, SidePanel, ...
    │   ├── wall/         /wall
    │   ├── org/          /o/<id> and /orgs
    │   ├── member/       /m/<id> sections: ties, ledger, trades, holdings, timeline, printable case file
    │   ├── records/      /m/<id>/records (the full file)
    │   └── shared/       used by several pages: EvidenceDrawer, TieTable, Print, SearchBox, controls, Assume
    ├── lib/
    │   ├── types.ts      the contract's types, copied verbatim from the data dictionary
    │   ├── format.ts     every money figure, range, date, count and seat label
    │   ├── copy.ts       fixed wording: site name, tagline, disclaimer, notices, "what this does not show", Case wording
    │   ├── urls.ts       every link: routes, data files, official record pages, safeHttpUrl for links from data
    │   ├── years.ts      YEAR_MIN / YEAR_MAX (the data's current year) and holdings years
    │   ├── hash.ts       FNV hash (tilts, seeds) and the org shard name
    │   ├── data/         loading: server.ts (build-time reads), fetch.ts (browser), decode.ts (columnar → objects), meta.ts, source.ts
    │   ├── domain/       rules: edges (tie vocabulary, amounts), pick (board strings), featured, assume, wallyears, party, holdings, records, names
    │   └── board/        board geometry: layout (card placement, yarn curves), fray (worn yarn), geo (map projection)
    └── styles/           tokens.css (colours, type, spacing) → globals → board → pages; reach, records, casefile per page
```

Rules of thumb: pure logic lives in `src/lib` and imports other lib files with an explicit `.ts` extension, so `node --test` can load it without a bundler; components never format numbers or build URLs themselves; anything a reader sees as fixed wording is in `lib/copy.ts`.

## Main journeys and the files behind them

| Journey | Route | Files |
|---|---|---|
| Open the site, see the featured example, pick a state and a member | `/`, `/?s=CA&m=<id>` | `app/page.tsx` (build-time props, featured ranking via `lib/domain/featured.ts`), `components/board/BoardApp.tsx` (selection + URL), `useBoardData.ts` (loads `/board-data/<state>`, `/board-member/<id>`, org shards), `BoardCanvas.tsx` + `yarn.tsx` + `lib/board/layout.ts` (drawing), `lib/domain/pick.ts` (which strings) |
| Open a string's evidence | drawer on any page | `components/shared/EvidenceDrawer.tsx`, `lib/domain/edges.ts` (labels, amounts), `lib/copy.ts` (not shown) |
| Change assumptions (whose trades count) | `?as=own,…` | `lib/domain/assume.ts` (rules), `components/shared/Assume.tsx` (UI, URL) |
| Read a member's case file | `/m/<id>` | `app/m/[id]/page.tsx`, `components/member/*` |
| Download every record | `/m/<id>/records` | `components/records/RecordsView.tsx`, `DataTable.tsx`, `lib/domain/records.ts` (tables, CSV), `lib/domain/holdings.ts` |
| See everyone at once, or one year | `/wall`, `/wall?y=2012` | `components/wall/WallView.tsx`, `lib/domain/wallyears.ts`, `lib/domain/party.ts` |
| Look at an organisation | `/o/<id>` (rewritten to `/org`), `/orgs` | `components/org/OrgView.tsx`, `OrgReach.tsx`, `OrgsBrowse.tsx` |
| Cases and method | `/cases`, `/method` | `app/cases/page.tsx`, `app/method/page.tsx` |

## How data is resolved

`scripts/resolve-data.mjs` (run before `dev` and `build`) and `src/lib/data/source.ts` (used by `next.config.ts` and the server code) apply one rule:

| `PT_DATA` | Uses |
|---|---|
| `fixtures` | fixtures, always |
| `real` | `public/data` whenever `members.json` exists |
| unset | `public/data` when its `meta.json` has `publication_budget` (a current-contract build), else fixtures |

On fixtures the files are copied to `public/sample-data/` (gitignored) and every page carries a SAMPLE DATA stamp. The browser reads the base path from `NEXT_PUBLIC_DATA_BASE` and the data's current year from `NEXT_PUBLIC_YEAR_MAX` (both set in `next.config.ts`).

- **Build time (server)**: `lib/data/server.ts` reads `members.json`, member files, `cases.json`, `meta.json` and so on with `fs`. Nothing reads data at request time, and `outputFileTracingExcludes` keeps the JSON out of server bundles.
- **Build-time JSON routes**: `/board-data/<STATE>` (each current member's board strings and node names), `/board-member/<id>` (former members), `/search-index` (members and the 6,000 largest organisations, so `orgs.json` never ships).
- **Browser**: `lib/data/fetch.ts` `getJSON` fetches each URL once per page load and rejects on non-2xx; `decode.ts` turns columnar tables (trades, ledger, org ties) into objects. Organisation pages load `orgs/<sha1(id)[0:2]>.json`; a tie with an `edge` id loads that member's file for its evidence.
- **Contract rules the UI keeps**: amounts are ranges (`amountText`, never a midpoint); missing is never zero; owner is shown as filed; `ledger_totals` covers ties that are *not* listed, so totals are listed + ledger (`orgTieTotal`).

## Run, test, screenshot

```bash
cd web
npm install
npm run dev                         # http://localhost:3000
npm run build                       # prebuild picks the dataset; postbuild runs eslint
npx next start -p 3100
npm test                            # unit tests + Playwright smoke tests (starts its own server on :3123 unless BASE_URL is set)
BASE_URL=http://localhost:3100 npm test
node --test tests/logic.test.mjs    # one unit file, no server
```

Tests use the pre-installed `playwright` package (`require('playwright')`), not `@playwright/test`.

Screenshots and visual regression (server running on :3100):

```bash
node scripts/visual-snapshots.mjs capture /tmp/before        # 19 fixed views, desktop and 390px, animations settled
# ...change code, rebuild, restart the server...
node scripts/visual-snapshots.mjs capture /tmp/after
node scripts/visual-snapshots.mjs compare /tmp/before /tmp/after   # differing pixels per view
node scripts/bundle-sizes.mjs                                # first-load JS per route
node scripts/screenshots.mjs http://localhost:3100 <memberId>  # ad-hoc screenshots into .screenshots/
```

Two captures of the same build differ by up to a few hundred pixels on the board (yarn anti-aliasing), so treat counts under ~1,000 on board views as noise.

## Where to change X

| To change | Edit |
|---|---|
| Site name, tagline, disclaimer, corrections email | `src/lib/copy.ts` (`SITE`) |
| "What this does not show" for a tie type, Case wording, legal notices | `src/lib/copy.ts` |
| A tie type's label, rule sentence or family hint | `src/lib/domain/edges.ts` (`TYPE_LABEL`, `TYPE_RULE`, `FAMILY_HINT`) |
| How money, ranges, dates or seats are written | `src/lib/format.ts` |
| Which strings the board draws for a member | `src/lib/domain/pick.ts` (tests: `tests/pick.test.mjs`) |
| How cards are placed or the yarn curves | `src/lib/board/layout.ts`, `src/components/board/yarn.tsx` |
| The featured example | `src/lib/domain/featured.ts` |
| Assumption switches | `src/lib/domain/assume.ts` |
| Wall measures or the year logic | `src/components/wall/WallView.tsx`, `src/lib/domain/wallyears.ts` |
| Colours, fonts, spacing | `src/styles/tokens.css` |
| A link to an official record built from an id | `src/lib/urls.ts` (`recordUrlFor`) |
| Columns in the full file or the CSV | `src/lib/domain/records.ts`, `src/lib/domain/holdings.ts` |

## Deploy on Vercel

Create a project with **Root Directory `web`**, framework Next.js, default build command (`npm run build`). No environment variables are required. Set `PT_DATA=fixtures` to force the sample build. Everything is prerendered; data files are excluded from server bundles. Geometry: `public/geo/us-states.json` (us-atlas states-10m); if it is missing in development, `resolve-data` caches a copy in `.cache/`.
