# Paper Trail (web)

The public site: a board that maps every member of Congress to the organisations and colleagues they are tied to by filed records, with the records one click away. Next.js 16 App Router, TypeScript strict, plain CSS, d3-geo and topojson-client (used at build time only). No database and no server secrets: every page is static.

The name and tagline are in `src/lib/site.ts`. Change them there.

## Run

```bash
cd web
npm install
npm run dev          # http://localhost:3000
```

## Build and test

```bash
npm run build        # prebuild picks the dataset; postbuild runs eslint
npx next start -p 3100
npm test             # Playwright smoke tests (starts its own server on :3123 unless BASE_URL is set)
BASE_URL=http://localhost:3100 npm test
node scripts/screenshots.mjs http://localhost:3100 <memberId>   # screenshots into .screenshots/
```

Tests use the pre-installed `playwright` package (`require('playwright')`), not `@playwright/test`.

## Where the data comes from

The data contract is `../docs/data-dictionary.md`; its types are copied verbatim into `src/lib/types.ts`.

- **Real data**: `public/data/`, written by the pipeline. The site never writes there.
- **Fixtures**: `fixtures/data/`, generated by `npm run fixtures` (`scripts/make-fixtures.mjs`): twelve invented members, invented companies, every edge type, cases, weak and derived edges, null tickers and unstated owners.

`scripts/resolve-data.mjs` (run before `dev` and `build`) and `src/lib/source.ts` (used by `next.config.ts` and the server code) apply one rule:

| `PT_DATA` | Uses |
|---|---|
| `fixtures` | fixtures, always |
| `real` | `public/data` whenever `members.json` exists |
| unset | `public/data` when its `meta.json` has `publication_budget` (a current-contract build), else fixtures |

On fixtures the files are copied to `public/sample-data/` (gitignored) and every page carries a SAMPLE DATA stamp and banner. The browser reads the data base path from `NEXT_PUBLIC_DATA_BASE`, which `next.config.ts` sets.

Build-time derived files (all static):

- `/board-data/<STATE>`: each current member's board strings (`MemberFile.board`) and node names for one state.
- `/board-member/<id>`: the same for former members.
- `/search-index`: compact member and top-organisation index for search, so `orgs.json` is never shipped to the browser.

Organisation pages (`/o/<id>`) are one static shell (`/org`, via a rewrite) that loads the org shard in the browser; ties with an `edge` id load the member file for evidence when opened.

Geometry: `public/geo/us-states.json` (us-atlas states-10m). If it is missing in development, `resolve-data` caches a copy in `.cache/`.

## Deploy on Vercel

Create a project with **Root Directory `web`**, framework Next.js, default build command (`npm run build`). No environment variables are required. Set `PT_DATA=fixtures` to force the sample build. Data files are excluded from server bundles (`outputFileTracingExcludes`); everything is prerendered.
